# 3) ตารางความยาก

## เป้าหมาย
ยิ่งได้คะแนนมาก เกมยิ่งยาก โดยคุมจากตารางเดียว

---

## แนวคิด — ตารางความยาก

```python
LEVELS = [
    {"name": "ง่าย", "gap": 200, "speed": 2, "at": 0},
    {"name": "ปกติ", "gap": 160, "speed": 3, "at": 5},
    {"name": "ยาก", "gap": 130, "speed": 4, "at": 12},
    {"name": "โหด", "gap": 110, "speed": 5, "at": 20},
]
```

| คีย์ | หมายถึง |
|------|---------|
| `name` | ชื่อระดับ (ไว้โชว์บนจอ) |
| `gap` | ช่องว่างระหว่างท่อ — **น้อย = ยาก** |
| `speed` | ท่อวิ่งเร็วแค่ไหน |
| `at` | ใช้ระดับนี้เมื่อคะแนนถึงเท่าไร |

---

## แนวคิด — เลือกระดับจากคะแนน

```python
def current_level():
    result = LEVELS[0]
    for lv in LEVELS:
        if score >= lv["at"]:
            result = lv
    return result
```

```text
score = 0   →  ผ่านเงื่อนไขแค่ "ง่าย"        →  ง่าย
score = 7   →  ผ่าน ง่าย, ปกติ              →  ปกติ  (ตัวท้ายสุดที่ผ่าน)
score = 25  →  ผ่านทุกระดับ                 →  โหด
```

> ไล่จากบนลงล่าง **เก็บตัวท้ายสุดที่ผ่านเงื่อนไข** — เลยต้องเรียงตารางจากง่ายไปยาก
> (ถ้าใช้ `elif` ต้องเรียงจากยากไปง่าย — เรื่องลำดับเงื่อนไขอีกแล้ว!)

---

## แนวคิด — เอาค่าจากตารางมาใช้

```python
level = current_level()
gap = level["gap"]
speed = level["speed"]

for pipe in pipes:
    pipe["x"] = pipe["x"] - speed      # ← ใช้ค่าจากตาราง
```

แล้วโชว์ชื่อระดับบนจอ

```python
screen.blit(font.render("ระดับ: " + level["name"], True, "white"), (600, 24))
```

## 🧪 ลองปรับตารางดู

| ลองเปลี่ยน | ผลที่ได้ |
|-----------|----------|
| `"gap": 250` ในระดับง่าย | เด็กเล็กเล่นได้ง่ายขึ้นมาก |
| `"at": 3` ในระดับปกติ | ยากเร็วขึ้น |
| เพิ่ม `{"name": "นรก", "gap": 95, "speed": 7, "at": 30}` | มีระดับใหม่ทันที |

> ลองแก้แค่ตัวเลขในตาราง แล้วเล่นดู — **ไม่ต้องแตะโค้ดส่วนอื่นเลยแม้แต่บรรทัดเดียว**
> นี่คือพลังของ data-driven 📊
